# AGV 现场记录 App（agv_app）

> 方案设计人员**在手机上**记录 AGV 项目需求：点模块填、拍照录视频、一键导出**格式与公司空白调研表完全一致**的 xlsx + 附件压缩包。
> **数据 100% 存在本机**，不上传任何服务器、无账号、不联网也能用。

---

## 一、为什么是这个形态（先看这段，避免走弯路）

| 你的要求 | 结论 |
|---|---|
| 安卓和 iOS 功能尽量相同 | ✅ 同一份代码，两端行为一致 |
| 网盘/链接分发，不走应用商店 | ✅ 安卓/iOS 都只需「添加到主屏幕」 |
| 不花钱 | ✅ 只需一个免费静态托管 |
| 数据不外泄 | ✅ 数据只在手机本地数据库，托管站上只有程序 |
| 现场可能没网 | ✅ 首次加载后完全离线可用 |
| 要能录视频 | ✅ App 内录制（720p/1.5Mbps，体积天然可控） |

**为什么不打包成原生 App**：iOS 装 `.ipa` 必须签名（Apple 开发者账号 $99/年；免费的 AltStore 7 天就过期）。"网盘发安装包"在 iOS 上走不通，而安卓能装。**只要你要双端一致 + 免费分发，PWA 是唯一解。**
未来若愿意每年花 $99，可用 Capacitor 把同一套前端包成真 App，代码不用重写。

## 五、怎么用

```
① 首页「我的方案」
   ＋ 新建方案（填客户名/项目名）
   卡片显示：客户 · 完成度 % · 草稿/已完成 · 最后修改
   顶部黄条：从未备份 / 已 N 天未备份  ← 请重视

② 工作台（点方案进入）
   九宫格模块卡片，每块显示「已填/总数」和状态
   底部：📷 快速记录（先拍照，稍后归类） · 导出

③ 模块编辑页（点卡片进入）
   改一笔立即落盘（顶部显示"已保存 hh:mm"）
   重复组（物料A/载具B/组合C/流程D）默认各 1 组，点「＋ 添加」可增
   组合 C 顶部两个下拉：由哪个物料 + 哪个载具（S3 语义）
   「保存并返回」回工作台
```

### 数值怎么填（没有滑块）

四种方式任选：**精确值 / 范围 / 大于等于 / 不确定**
- 温度、载重、节拍 → 用「范围」（如 `5 ~ 30 ℃`）
- 通道宽度、承重 → 用「大于等于」
- 尺寸类 → 精确值
- 拿不准选「不确定」，导出的表里会写"不确定/待确认"，**不会被当成漏填**

### 附件
工作台 →「附件」卡片：
- 现场照片 / 物料载具照片 / 图纸（图片自动压缩到长边 1920、约 200~500KB）
- 现场视频：点「🎥 录制视频」（720p，单段建议 ≤2 分钟）；也可从相册选
- 每个附件点一下可加**说明**（如"1F 地面接缝"），导出时成为文件名的一部分

### 导出
点「导出」→ 得到 zip：

```
삼양식품_20261104.zip
├─ 1.1 AGV项目需求调研表_삼양식품_20261104.xlsx   ← 格式与空白表一致，没填的留空
├─ 现场照片/  01_xxx.jpg …
├─ 现场视频/  01_xxx.mp4 …
├─ 图纸/
├─ answers.json        原始数据（可再生成表格 / 后续喂选型工具）
└─ 说明.txt
```

- **附件较大或含视频时**会问你是否**分包导出**（表格+照片 一包、视频 一包）——iOS 上更稳
- **超出原表预留位置的内容**（物料 A3、载具 B2、组合 C3…，以及"选型补充""其他需求"）统一写在表格 **R84 起的【扩展区】**，不会破坏原表格式

## 六、数据安全与"千万别丢"

| 项 | 说明 |
|---|---|
| 数据在哪 | 手机浏览器的 IndexedDB（照片视频也是） |
| 会上传吗 | **不会**。整个 App 没有上传代码路径 |
| 换手机会怎样 | 看不到旧数据（除非你导出过 zip） |
| 清浏览器数据/卸载 | **全部丢失** |
| iOS 特别注意 | 长期不打开，系统可能清理站点数据 → 到现场前先打开一次 |
| 唯一可靠办法 | **定期导出 zip**，存网盘/电脑/发给自己 |

App 里已经内置防丢提醒：首页黄条按天数变色（3 天提醒、7 天变红），每次导出会记录时间。

### 加密导出（可选）
- 加密：**工作台 → ⋯ → 加密导出**，设一个 ≥6 位口令，产物为 `<原名>.zip.enc`（AES-GCM 256 + PBKDF2 12 万次）
- 解密：**首页 → ⋯ → 解密加密包**，选 `.zip.enc` 输口令，还原成普通 zip
- 适合通过微信/网盘传敏感资料。**口令丢了就打不开**，请自行保管

## 七、字段与原表的对应关系

字段定义全部来自 `docs/assets/schema.js`（59 个字段，覆盖原表 **75 个填写位置**）：

| 步 | 模块 | 对应原表 | 写入单元格 |
|---|---|---|---|
| 1 | 基本信息 | R2~R9 | D 列 |
| 2 | 物料信息（概述 + A1/A2…） | R11~R22 | F 列 |
| 3 | 载具信息（B1/B2…） | R23~R29 | F 列 |
| 4 | 载具+物料组合（C1/C2…，12 项尺寸） | R30~R54 | F 列 |
| 5 | 物流流程（D1/D2…） | R55~R64 | F 列 |
| 6 | 工艺流程 | R65 | C65（合并格，追加在原提示后） |
| 7 | 现场信息 + 工作模式 | R66~R75 | F 列 |
| 8 | 系统对接 | R76~R81 | F 列 |
| 9 | **选型必需补充**（原表没有） | — | R84+ 扩展区 |
| 10 | **其他需求**（指定车型/特殊条件） | — | R84+ 扩展区 |
| — | 附件 | — | zip 内独立目录 |

原表预留容量：物料 ×2、载具 ×1、组合 ×2、流程 ×2。超出的自动进扩展区。

## 八、技术实现（为什么能保证格式不变）

调研表 xlsx 本质是 ZIP。生成时：

1. 拆开模板（约 43KB，ZIP 内部十几个部件）
2. **只改 `xl/worksheets/sheet1.xml`** 里目标单元格（文本用 `inlineStr`，数值用 `<v>`）
3. 其余 36 个部件（图片、样式、41 个合并单元格定义）**原始压缩字节原样拷贝**
4. 重新拼 ZIP

所以格式不可能变。实测（`tests/test_xlsxgen.mjs`）：4.82 MB、34ms、**41 个合并单元格 / 17 张图片全部保留**、数值是数值类型、未填字段保持空白。

## 十一、改字段怎么办

只改 `docs/assets/schema.js`，三处要同步：
1. `schema.js` 里加字段定义
2. `xlsxgen.js` 的 `FIXED` / `REPEAT` 映射里加对应单元格（否则不会写进表）
3. 跑 `node agv_app\tests\test_xlsxgen.mjs` 确认落位正确
